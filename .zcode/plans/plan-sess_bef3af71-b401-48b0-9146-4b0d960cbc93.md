# 在 lynse-mcp 中加入「应用授权记录」（对齐 biji.com 开放平台）

## Context

调研了 biji.com 开放平台 `/openapi?tab=auth` 的「应用授权记录」：用户在网页控制台查看并管理通过 OAuth/MCP 连接器接入的应用授权。核心要素：

- **记录字段**：`authorization_id`、`client_id`/`client_name`、`grant_type`、`scopes[]`、`status`（valid/expired/revoked）、`authorized_at`/`expires_at`
- **操作语义**：valid →「撤销授权」（确认弹窗）；revoked/expired →「删除」；记录保留至用户删除
- **API**：分页列表 + revoke + delete，登录会话鉴权

lynse-mcp 已有完整 OAuth grant 体系（PKCE + 网站桥接 + RFC 7009），但：grant 记录不含 `client_name`/`authorized_at`；撤销是物理删除、无历史可展示；网站侧没有列出/管理授权的 API。授权页前端在主站仓库（www.lynse.cn/platform/oauth），本仓库交付**后端桥接 API + 契约文档 + test UI 自测管理页**（用户已确认）。

## 改动

### 1. `lynse_oauth_store.py` — 按需扫描能力
新增 `scan(db, kind)`：`SELECT id, payload FROM records WHERE kind=?`，逐行解密并校验 envelope 后 yield `(id, value)`。不能复用 `read()`（它跳过行级 expires 过期的记录；授权记录的"业务过期"要继续展示，行级 expires 仅作保留期限）。

### 2. `lynse_remote.py` — 核心（四处）

**a. 授权记录落库**（`WebsiteBridge.handle` 的 consent allow 分支）：创建 grant 的同时写一条 `authorization` 记录，key=grant_id，payload `{subject, client_id, client_name, scopes, authorized_at, grant_expires, status:"valid", revoked_at:None}`，**不含任何机密**（无 upstream_token/token 值）；行级 expires = grant_expires + 180 天保留期。client_name 取自 pending 记录（已有）。

**b. 撤销/删除共享逻辑**：新增 `_revoke_grant(db, grant_id)` — 删 grant、`scan` access/refresh 删除 grant_id 匹配的 token 记录、authorization 标记 `status:"revoked"` + `revoked_at`，保留期改为 now+180 天。
- `AccountOAuthProvider.revoke_token`（RFC 7009 路径）改用该 helper → 客户端侧撤销后记录以「已吊销」保留。
- 桥接撤销：校验 authorization 存在、subject 与登录会话一致（账号隔离）、状态为 valid。
- 桥接删除：仅允许 revoked 或 expired（grant_expires ≤ now）状态，物理删除记录行。

**c. 账号级桥接 action（无 ticket）**：`handle()` 重构 — `context`/`consent` 仍要求 ticket；登录类（`sms`/`phone-login`/`logout`/`wechat-start`/`wechat-complete`）允许无 ticket（管理页入口）；新增：
- `GET authorizations`：需已登录浏览器会话；返回 `{user:{name}, csrf, authorizations:[{authorization_id(=grant_id), client_id, client_name, grant_type:"oauth", scopes, status, authorized_at, expires_at}]}`，authorized_at 倒序。status 计算：payload 为 revoked → revoked；grant_expires≤now → expired；否则 valid。
- `POST authorization-revoke` / `authorization-delete`：要求登录 + `Origin == web_origin` + `x-mcp-csrf` 与会话 csrf 恒定时间比较 + 现有 per-peer 限流。会话 csrf 在 `_save_session` 登录时生成（`secrets.token_urlsafe(32)`）。
- 未登录返回 400 + 中文提示（沿用 AccountError 风格，如「请先登录你的 Lynse 账号。」）。

**d.** 确认 `OAuthSecurityMiddleware` 对 API_PATH 的限流/no-store 已覆盖新 action（预计无需改动）。

### 3. `lynse_test_client.py` — test UI「我的授权」页（`LYNSE_MCP_TEST_UI=1` 时）
`GET /platform/oauth/test/authorizations`：服务端渲染（沿用 `page()` 模板、无 JS）。
- 未登录：手机号+验证码表单（发送验证码/登录两个提交），POST 到 test 路由，服务端用 `_request` HTTP 转发真实桥接 API（携带浏览器 cookie，端到端验证契约），PRG 重定向回本页。
- 已登录：渲染记录列表（同样经 HTTP 调 `GET authorizations`），每条按状态显示「撤销授权」/「删除」表单按钮（hidden 授权 id + 会话 csrf），服务端转发对应桥接 API。

### 4. 测试 — `tests/test_account_oauth.py` 追加
- 列表：授权后字段/状态正确；两用户、两客户端互相隔离。
- 撤销：access 立即失效（`verify_token` None）、refresh 报 invalid_grant、记录变 revoked 仍在列表；RFC 7009 撤销同样标记 revoked。
- 过期/删除：patch time 过期 → 状态 expired；delete 后从列表消失；valid 状态 delete 被拒。
- 安全：未登录 400；错 Origin/CSRF 403；跨用户撤销被拒；响应不含 upstream_token 与 token 明文；无 ticket 可登录但 consent 仍需 ticket。
- test UI 管理页 smoke：未登录显示表单、登录后渲染并可撤销。

### 5. 文档与版本
